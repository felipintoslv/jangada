## Apontamentos

### 1. Chamada de funções Lua em comandos hyprctl dispatch externos
- Arquivo e linha: bin/jangada-agentes:55, bin/jangada-agentes:104, bin/jangada-menu:44, default/hypridle/hypridle.conf:7, 17, 18
- Gravidade: alto
- Certeza: alta
- Problema: O comando hyprctl dispatch se comunica via soquete IPC com o despachante interno em C++ do Hyprland. Ele espera o nome do despachante nativo e seus argumentos textuais (por exemplo: focuswindow, togglespecialworkspace, dpms, exit). Passar tabelas e chamadas da API Lua como 'hl.dsp.exit()', 'hl.dsp.workspace.toggle_special("agentes")', "hl.dsp.focus(...)" ou 'hl.dsp.dpms(...)' faz com que o Hyprland rejeite a instrução por despachante inexistente.
- Correção proposta:
Em bin/jangada-agentes:
```bash
# linha 55
hyprctl dispatch focuswindow "address:$endereco" >/dev/null

# linha 104
hyprctl dispatch togglespecialworkspace agentes >/dev/null
```
Em bin/jangada-menu:
```bash
# linha 44
"Sair da sessão") hyprctl dispatch exit ;;
```
Em default/hypridle/hypridle.conf:
```conf
# linha 7
after_sleep_cmd = hyprctl dispatch dpms on

# linhas 17 e 18
on-timeout = hyprctl dispatch dpms off
on-resume = hyprctl dispatch dpms on
```

### 2. Uso direto de sudo e ausência de cópia de segurança em install/40-interface.sh
- Arquivo e linha: install/40-interface.sh:43
- Gravidade: médio
- Certeza: alta
- Problema: Na gravação do arquivo de sessão /usr/share/wayland-sessions/jangada.desktop, o script invoca sudo tee diretamente em vez da função como_root definida em install/lib.sh. Além disso, se o arquivo já existir no sistema com conteúdo prévio, é sobrescrito sem passar por copia_seguranca, violando as regras 2 e 3 de AGENTS.md.
- Correção proposta:
```bash
  copia_seguranca "$_sessao"
  if simulando; then
    info "[simulação] gravaria $_sessao"
  else
    printf '%s\n' "$_conteudo" | como_root tee "$_sessao" >/dev/null
  fi
```

### 3. Encerramento prematuro da sessão tmux em jangada-agente-fim
- Arquivo e linha: bin/jangada-agente-fim:45
- Gravidade: alto
- Certeza: alta
- Problema: O script executa kill-session na linha 45, antes de remover o worktree (linhas 47 a 55) e antes de apagar o arquivo de estado JSON (linha 57). Se o comando for disparado de dentro da própria sessão tmux do agente, o encerramento da sessão envia sinal de término imediato ao processo da shell, interrompendo o script antes da remoção do worktree e do arquivo de estado.
- Correção proposta:
Mover a instrução kill-session para depois das etapas de limpeza do diretório de trabalho e do estado:
```bash
if [[ -n "$worktree" && -d "$worktree" ]]; then
  if ((forcar)); then
    git -C "$raiz" worktree remove --force "$worktree"
  else
    git -C "$raiz" worktree remove "$worktree"
  fi
  echo "worktree removido: $worktree"
  [[ -n "$ramo" ]] && echo "ramo mantido: $ramo (apague com: git -C $raiz branch -d $ramo)"
fi

rm -f "$arq"
"${JANGADA_TMUX[@]}" kill-session -t "=$s" 2>/dev/null || true
echo "sessão encerrada: $s"
```

### 4. Falha de jangada-tema --escolher quando pastas de imagens não existem
- Arquivo e linha: bin/jangada-tema:41-44
- Gravidade: baixo
- Certeza: alta
- Problema: O laço de busca por pastas de papel de parede não interrompe caso nenhuma das opções exista, fazendo com que pasta assuma $HOME/Pictures mesmo inexistente. Com o modo set -euo pipefail ativo, o comando find falha e aborta o script.
- Correção proposta:
```bash
  for pasta in "$HOME/Imagens/Papeis" "$HOME/Pictures/Wallpapers" "$HOME/Imagens" "$HOME/Pictures"; do
    [[ -d "$pasta" ]] && break
  done
  [[ -d "$pasta" ]] || { echo "nenhuma pasta de papéis de parede encontrada" >&2; return 1; }
```

### 5. Arquivos sensíveis adicionais no filtro de mapeamento
- Arquivo e linha: bin/jangada-mapear:25
- Gravidade: médio
- Certeza: alta
- Problema: A expressão regular ignorar_regex lista id_rsa e id_ed25519, mas não inclui id_ecdsa, id_dsa ou arquivos como .netrc, .pgpass e .env. Embora a etapa seguinte aplique substituições por expressões regulares em conteúdos de texto, impedir a cópia desses arquivos na origem evita vazamento acidental caso a estrutura do arquivo fuja do padrão esperado.
- Correção proposta:
```bash
ignorar_regex='(\.pem|\.key|id_[a-z0-9_]+|\.env(\..*)?|\.netrc|\.pgpass|credentials|\.credentials\.json|auth\.json|oauth|cookies|\.sqlite|\.db|history|\.log)$'
```

### 6. Risco de falha em snapper create-config com diretório existente desmontado
- Arquivo e linha: install/20-snapshots.sh:25-36
- Gravidade: médio
- Certeza: alta
- Problema: O comando snapper -c root create-config / falha se a pasta /.snapshots já existir no sistema de arquivos, mesmo que vazia. Caso ela exista sem estar montada como subvolume (mountpoint -q retorna falso), o script cai no bloco else e falha com erro de arquivo existente.
- Correção proposta:
```bash
    if mountpoint -q /.snapshots 2>/dev/null; then
      info "/.snapshots já é um subvolume montado; aplicando o procedimento padrão"
      como_root umount /.snapshots
      como_root rmdir /.snapshots
      como_root snapper -c root create-config /
      como_root btrfs subvolume delete /.snapshots
      como_root mkdir /.snapshots
      como_root mount -a
      como_root chmod 750 /.snapshots
    else
      [[ -d /.snapshots ]] && como_root rmdir /.snapshots 2>/dev/null || true
      como_root snapper -c root create-config /
    fi
```

### 7. Verificação de worktree órfão registrado no git
- Arquivo e linha: bin/jangada-agente:81-85, bin/jangada-agente-fim:47-55
- Gravidade: baixo
- Certeza: média
- Problema: Se uma pasta de worktree for excluída manualmente sem desregistrar no git, o comando git worktree add pode recusar a criação acusando que o caminho já é um worktree registrado.
- Correção proposta:
Executar git -C "$raiz" worktree prune antes de checar a existência ou ao remover a sessão.

### 8. Validação de TOML restrita ao Python 3.11+ em testes estáticos
- Arquivo e linha: testes/verificar.sh:51, 54-61
- Gravidade: baixo
- Certeza: alta
- Problema: O script de teste usa import tomllib diretamente. Em ambientes de desenvolvimento fora do Arch com versões anteriores de Python (como Python 3.9 no macOS), o teste acusa erro por ausência do módulo interno do Python 3.11.
- Correção proposta:
Adicionar compatibilidade condicional (tentar tomllib e tomli, ou ignorar graciosamente se nenhum estiver instalado):
```bash
python3 -c '
try:
    import tomllib as toml
except ImportError:
    try:
        import tomli as toml
    except ImportError:
        import sys; print("tomllib/tomli ausente; etapa ignorada"); sys.exit(0)
import sys
toml.load(open(sys.argv[1], "rb"))
' default/matugen/config.toml || falha "matugen/config.toml"
```

## O que está correto

1. **Estrutura e isolamento:** A separação estrita de arquivos entre o repositório de padrões, ~/.config/jangada e ~/.local/state/jangada cumpre integralmente os princípios de isolamento sem interferir nas configurações existentes do Hyprland ou do Noctalia.
2. **Atualização do sistema:** O script bin/jangada-update trata com precisão a questão dos pacotes integrados do Hyprland, impedindo atualizações parciais arriscadas e alertando o usuário sobre mudanças de versão e snapshots pelo snap-pac.
3. **Mapeamento seguro:** O script bin/jangada-mapear realiza varredura ampla sem comandos invasivos, aplicando máscara em chaves de API, senhas e tokens sensíveis.
4. **Gerenciamento de agentes:** O fluxo de trabalho com tmux isolado (soquete -L jangada), git worktree e acompanhamento de ciclo de vida via hooks JSON do Claude Code funciona de forma desacoplada e segura.
5. **Configuração Lua modular:** O mecanismo de recarga com limpeza de tabela package.loaded em default/hypr/bootstrap.lua e a abstração das chamadas em default/hypr/ajudantes.lua seguem a arquitetura do Hyprland 0.55+.
