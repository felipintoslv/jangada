# Revisão do jangada (20260921-0909)

### 1. Interrupção por set -e ao reaproveitar worktree existente
- Arquivo e linha: `bin/jangada-agente:94` e `bin/jangada-par:162`
- Gravidade: crítico
- Certeza: alta
- Problema: Sob `set -euo pipefail`, a avaliação aritmética `(( 0 ))` retorna código de saída 1. Como a linha `((worktree_novo)) && ...` é uma instrução isolada (não um teste de `if`), quando um worktree existente é reaproveitado a variável `worktree_novo` permanece `0`. Nesse caso, `((worktree_novo))` falha, a expressão `&&` é interrompida com status 1 e o Bash aborta o script imediatamente por causa de `set -e`, impedindo a inicialização da sessão.
- Correção proposta:
```bash
  if ((worktree_novo)); then
    "$JANGADA_PATH/bin/jangada-worktree-preparar" "$raiz" "$worktree"
  fi
```

### 2. Aborto do script de preparo quando não há arquivos copiados ou ligados
- Arquivo e linha: `bin/jangada-worktree-preparar:137`
- Gravidade: crítico
- Certeza: alta
- Problema: Se o repositório não possuir `.worktreeinclude` nem `.jangada/links` (ou se nenhum arquivo casar com as regras), as variáveis `copiados` e `ligados` continuam com valor 0. A expressão `((copiados + ligados)) && echo ...` avalia para `(( 0 ))`, resultando em código de saída 1. Sob `set -euo pipefail` (linha 20), o Bash aborta o script na linha 137, fazendo com que a etapa 3 (`.jangada/preparar.sh`) nunca seja executada e retornando erro para `jangada-agente` ou `jangada-par`.
- Correção proposta:
```bash
if ((copiados + ligados)); then
  echo "preparar: $copiados copiado(s), $ligados link(s) em $worktree"
fi
```

### 3. Falha no git ls-files com caminhos com espaços ou caracteres UTF-8
- Arquivo e linha: `bin/jangada-worktree-preparar:74`
- Gravidade: médio
- Certeza: alta
- Problema: Por padrão no Git, `core.quotePath` é `true`. Se um arquivo ignorado contiver espaços, acentos ou caracteres especiais, `git ls-files` coloca o caminho entre aspas duplas e escapa caracteres não-ASCII em octal (ex.: `"caminho com espaco"` ou `"dados/\303\241rea"`). O `mapfile` captura as aspas e sequências octais como texto literal, fazendo com que `caminho_seguro`, `git check-ignore` e `cp` falhem ao manipular o caminho.
- Correção proposta:
```bash
  mapfile -t candidatos < <(git -C "$raiz" -c core.quotePath=false ls-files --others --ignored --directory \
    --exclude-from="$raiz/.worktreeinclude" 2>/dev/null || true)
```

### 4. Correspondência estrita do título da janela em proximo()
- Arquivo e linha: `bin/jangada-agentes:149`
- Gravidade: baixo
- Certeza: média
- Problema: A comparação `if [[ "${fila[i]}" == "$atual" ]]; then` exige igualdade exata entre o título da janela ativa e o nome da sessão tmux. Se a configuração de terminal do usuário acrescentar qualquer texto ao título (ou se o terminal não aplicar o escape OSC do tmux a tempo), a janela ativa não é reconhecida como elemento da fila. Com isso, apertar `SUPER + N` repetidas vezes seleciona sempre o primeiro da lista em vez de alternar entre os agentes. A função `focar()` no mesmo arquivo (linha 113) trata isso com busca flexível (`.title == $s or (.title | test($s))`).
- Correção proposta:
```bash
  for ((i = 0; i < n; i++)); do
    if [[ "$atual" == "${fila[i]}" || "$atual" == *"${fila[i]}"* ]]; then
      alvo="${fila[(i + 1) % n]}"
      break
    fi
  done
```

### 5. Heurística de reflink_provavel com subvolumes Btrfs separados
- Arquivo e linha: `bin/jangada-worktree-preparar:60-66`
- Gravidade: baixo
- Certeza: alta
- Problema: No Btrfs, cada subvolume aloca um `st_dev` próprio no kernel. Se a raiz do projeto e a pasta de worktrees estiverem em subvolumes distintos do mesmo sistema de arquivos (por exemplo, `@projetos` e `@home`), `stat -c %d "$raiz"` será diferente de `stat -c %d "$worktree"`. Isso faz `reflink_provavel` retornar falso e acionar o limite de cópia `copia_max_mb` (500 MB), mesmo sendo um sistema Btrfs onde a cópia reflink ocorreria instantaneamente e sem ocupar espaço. A verificação pelo identificador do sistema de arquivos (`stat -f -c %i`) é mais estável para essa finalidade.
- Correção proposta:
```bash
reflink_provavel() {
  case "$(stat -f -c %T "$raiz")" in
    btrfs|xfs) ;;
    *) return 1 ;;
  esac
  [[ "$(stat -f -c %i "$raiz")" == "$(stat -f -c %i "$worktree")" ]]
}
```

## O que está correto

1. **Preparo de worktrees (`bin/jangada-worktree-preparar`):**
   - A função `caminho_seguro` bloqueia de modo eficaz caminhos absolutos e componentes `..`, impedindo ataques de escape de diretório a partir de repositórios de terceiros.
   - O uso de `--` em todos os utilitários de sistema (`cp`, `ln`, `rm`, `du`, `mkdir`, `git`) impede que arquivos com nomes iniciando em `-` sejam interpretados como opções.
   - A conferência com `git -C "$worktree" check-ignore -q -- "$c"` após a criação de links simbólicos evita que diretórios ignorados sem a barra final no `.gitignore` sejam acidentalmente rastreados como arquivos no repositório do worktree.
   - A proteção `[[ -e "$worktree/$c" || -L "$worktree/$c" ]]` impede sobrescrever arquivos rastreados do git ou links quebrados preexistentes.

2. **Fila de atendimento de agentes (`bin/jangada-agentes --proximo` e atalho `SUPER + N`):**
   - A ordenação da fila (agentes aguardando resposta por ordem cronológica crescente e ciclos concluídos por ordem decrescente) prioriza corretamente tarefas bloqueadas.
   - O fallback com `"$0" --janela` quando o processo já encerrou ou não possui tmux ativo garante que o resultado fique visível e oferece `Ctrl+X` para descarte.
   - A atribuição do atalho `SUPER + N` em `default/hypr/atalhos.lua` usa `j.atalho` com descrição, integra-se ao `SUPER + /` e não conflita com nenhum atalho existente no composiador.

3. **Skill do Claude Code (`default/claude/skills/jangada`):**
   - O arquivo `SKILL.md` segue o padrão esperado pelo Claude Code, com metadados YAML (`name`, `description`) e documentação objetiva.
   - A função `ligar_skill_claude` em `install/lib.sh` é idempotente, respeita `JANGADA_SIMULAR=1` por meio de `executar`, preserva pastas existentes que não pertençam ao jangada e atualiza links apontando para caminhos antigos.
   - A migração `migrations/202609211000-skill-claude.sh` verifica a presença do Claude Code antes de agir e segue o padrão numérico de versão do projeto.
   - As notas técnicas registradas nos arquivos de documentação (`hyprland.md`, `interface.md`, `agentes.md`) são precisas quanto ao comportamento do Hyprland 0.55 Lua, Waybar com `setsid -f`, Hypridle e chamadas ao Antigravity CLI em modo não interativo.

4. **Pacotes em `install/pacotes/`:**
   - Todos os nomes listados em `base.txt`, `interface.txt`, `ferramentas.txt` e `snapshots.txt` correspondem exatamente a pacotes válidos dos repositórios oficiais do Arch Linux ou do AUR.

5. **Regras de estilo e documentação:**
   - As adições em `README.md` e `AGENTS.md` respeitam a regra de redação em português sem travessões e sem estrangeirismos desnecessários.
